# ANDO 0.9.168 repo check (2026-11-25)

After the global CLI was updated from 0.9.166 to 0.9.168, every repo in `~/Source` with a `*.csando` script was checked with `ando run --dry-run` for each script and profile (15 repos). No real runs, no deploys.

## Result

All build scripts compile and produce the expected step trees. No script needed a fix and no commits were made in other repos.

The new scratch-folder warning did not appear anywhere.

## Decisions for the owner

1. **SimpleSign365 ANDO pin.** Either run the release drill with 0.9.168 and raise `ando_pin`, or keep 0.9.166 installed until then (`dotnet tool update -g ando --version 0.9.166`). Until one of them happens, `scripts/release.sh` refuses to build or deploy.
2. **alexandria:** move `RunDotnetBuild`/`RunDotnetTest` to `Dotnet.Build`/`Dotnet.Test` with a test filter, so they run in the container and in step order.
3. **selfmx:** delete the shadowed root `ando-pre.csando`, or port its `gh auth token` fallback into `scripts/ando-pre.csando`.

## Proposed ANDO changes

Ordered by value.

1. **Dry runs without secrets.** A missing required env var (`Env("X", required)`, `Cloudflare.EnsureAuthenticated` prerequisites) fails `--dry-run --no-env`. In a dry run, report all missing variables in one warning and still print the step tree. Hit in 6 repos.
2. **Hook checking.** `ando run -f ando-pre.csando --dry-run` compiles a hook against the build-script globals and fails with misleading errors (`/workspace` for `Root`, no `Shell.RunAsync`, missing `ANDO_NEW_VERSION`). Add `ando hook check [file]` (compile only, against `HookGlobals`), or make `run -f` detect hook files and say so. Also warn when a root hook is shadowed by `scripts/<hook>`.
3. **Top-level code in dry runs.** Document clearly that script top-level code runs during a dry run, and consider a warning when a script starts processes at load time (alexandria).
4. **Deferred checks in dry runs.** `Ando.Require`/deferred values print their message in the tree, which reads like a failure. Mark them "(checked at run time)".
5. **Step tree assertion.** SimpleSign365 hand-rolls tree normalization and comparison (`release.csando:44-62`). Add `Ando.AssertStepTree(file, profiles, expectedFile)` with an update mode.
6. **`Git.CommitSubject`.** SimpleSign365 `build.csando:26-37` shells out to `git log` for it.
7. **Artifact-free deploy dry runs.** Deploy dry runs need a real `.run/release/<sha>` manifest. A dry-run flag to skip artifact verification would make tree checks easy.
8. **Child builds in the tree.** `Ando.Build(Directory("./website"))` shows as one step; optionally expand the child's tree in `--dry-run`.
9. **Bun.** Tongs runs bun on the host from a hook loop (`Tongs/ando-pre.csando:21`); a typed `Bun.*` provider would cover it.
